# StoryCut

[English](README.md) | [简体中文](README.zh-CN.md)

**AI proposes. The creator decides.**

StoryCut is a local review and feedback workspace for Codex video-editing workflows. It organizes previews, project memory, story plans, subtitles, and EDLs generated by Codex, then turns timecoded creator feedback into structured project files and an execution-ready Codex prompt.

This repository contains the first public-safe MVP created for OpenAI Build Week in the **Work and Productivity** category.

## What works

**v0.3 (Codex local review workspace)**

- Open an existing local video project or `edit/` directory
- Discover the latest review video, `project.md`, EDL, subtitles, transcripts, and packaging plans
- Cache recent projects and pending review notes in the current browser so work can be resumed with one click
- Refresh an open project to discover newly rendered previews, subtitles, BGM cues, and SFX markers
- Follow and correct the current subtitle at the top of the feedback panel; edits are stored in `edit/review/subtitle-corrections.json` without overwriting the source subtitle
- Review video and searchable subtitle/edit-node indexes in one workspace; manual seeking near a node automatically opens and locates the node list, while row clicks still jump precisely
- Keep the review-version selector limited to whole-film/version previews; clip proxies and animation assets stay out of the control to avoid large-project UI stalls
- Change playback speed from `0.5×` to `2.0×`
- Extract cuts, SFX, flower-text overlays, chapter cards, and BGM cues from EDL/packaging plans with filters and a compact whole-film overview
- Build and reuse a local H.264/AAC playback proxy for Video Review too, preserving position and falling back to project media if a proxy becomes unavailable
- Add intent-focused feedback at exact video ranges
- Capture must-keep notes, priority, and locked decisions
- Save each round as `edit/review/current.json`, Markdown records, and a Codex prompt
- Browse and preview local project documents by type
- Keep project paths, media, and feedback on the local machine

**v0.4 (conversational editing workspace)**

- Bring conversational notes, the current version's used media, preview, and a multi-track full-film timeline into one **Edit workspace**
- Read StoryCut schema-v2 `activeVersion` and version entries; switching `rough_cut_vN_rM` atomically changes preview, EDL, subtitles, packaging markers, and proxies
- Derive the media bin only from clips actually used by the selected version's EDL, list each matching `clips_preview/` or `clips_draft/` proxy separately, and seek the review video when a proxy is clicked
- Follow explicit `base_preview` links so incremental graphics revisions inherit earlier flower text and chapter cards
- Zoom the timeline from 1–8×, scroll horizontally, fit the whole film, click to seek, or drag the playhead; flower-text and chapter ranges use their real start/end times, readable captions avoid blank short blocks, and the ruler adapts its labeled major/minor ticks to zoom
- Bind every note to an editable start/end range, review version, preview file, playback time, and selected shot or packaging marker (flower text, chapter card, BGM, or SFX); multi-select, edit, or delete notes, then archive and clear the pending list when a Prompt is generated
- Restore an archived revision into the pending list to refine it and generate another Prompt
- Keep the current interface opinion-only: it does not write source media, EDLs, subtitles, or project files; notes and timeline view state stay in browser-local storage
- Generate browser-optimized H.264/AAC playback proxies for the selected A and B videos in either preview quality on the local SSD (1280 px max edge, about 2 Mbps, two-second GOP, MP4 `faststart`); work is single-job throttled, original media remains the fallback until ready, source fingerprints prevent stale reuse, and an adjustable LRU policy defaults to 20 GB
- Compare two review versions in sync: A remains the master player while muted B follows play, pause, rate, and timecode; switch between A-only, split, and B-only views with `\`, and inspect a clickable delta lane for added, removed, trimmed, extended, or moved clips and packaging markers
- Persist the project scan and a stable project ID on the local SSD; later opens and server restarts restore the session after validating only the active version and key files, while **Refresh project/Reload** still forces a complete scan
- Render large media bins in batches of 40 and replace per-clip synchronous-audio DOM groups with one lightweight waveform plus cut-boundary path
- Inspect global and current-project playback proxies, first-frame thumbnails, and project indexes from the local cache panel; clear only the current project's ownership, change the 1–200 GB proxy limit, or open the fixed cache directory in Finder

The original transcript analyzer now lives on the **AI Analysis** page.

**v0.1 (paste-transcript path)**

- Paste plain text, SRT, or VTT transcripts
- Run a deterministic local demo analyzer without an API key
- Optionally use GPT-5.6 through the server-side OpenAI Responses API
- Filter decisions and accept or reject every proposal
- Export reviewed decisions as timeline JSON
- Responsive, presentation-ready interface

**v0.2 (local media path)**

- Drop an mp4 / mov / m4a / wav / mp3 into the browser; the file never leaves the machine
- Server runs `tools/transcribe.py` over **MLX Whisper** on Apple Silicon and streams progress + the final timecoded transcript to the browser via SSE
- Word-level timestamps are preserved through transcription, alignment, and the existing decision engine
- Decisions from the media path land in the same review surface as the paste path

StoryCut is not a replacement for a professional timeline. Codex and local editing skills continue to generate the authoritative EDL, subtitles, packaging, and final renders; StoryCut turns review notes across multiple versions into a timecoded, asset-aware prompt for Codex to execute.

## Run locally

Requirements: Node.js 20 or newer. macOS on Apple Silicon with MLX Whisper for the v0.2 media path. ffmpeg / ffprobe (Homebrew) for ffprobe metadata.

```bash
npm start
```

Open <http://127.0.0.1:4173>, choose **Open project**, then enter a local project directory containing `edit/`.

On **Video review**, the current subtitle follows playback at the top of the feedback panel. Edit it and choose **Save correction** to record a pending, non-destructive revision. The player and index share one workspace, and manually seeking near a creative node automatically opens and locates the node list. Cuts, SFX, flower text, chapter cards, and BGM markers can also be filtered and clicked, and playback speed is adjustable.

On **Edit workspace**, choose the review version, select a source or shot, write a note, and choose **Add opinion**. Keep collecting notes across versions, then choose **Generate total prompt**. This workflow does not modify any project file.

The first time a version is opened, StoryCut builds its local playback proxy in the background and shows progress beside the preview controls. Playback falls back to the project video while it is being generated, then switches at the same timecode when ready. A source path, size, or modification-time change invalidates the old proxy automatically.

Choose **A/B compare** in the Edit workspace to compare two versions. A remains the only playback controller and B follows silently; use **A / Split / B** or `\` to change the view, and click the delta lane to inspect version changes. The **Cache** panel separates global and current-project use, supports project-safe clearing and a configurable proxy limit, and can open its fixed folder in Finder. Routine project opens reuse the persistent index; an explicit refresh performs a full rescan.

- For the **paste path** (works everywhere): choose **Load safe demo**, then **Analyze story**.
- For the **media path** (Apple Silicon): drop an mp4 / mov / m4a / wav / mp3 onto the upload zone, wait for transcription, and the same review surface opens with timecoded decisions.

No dependency installation is required for the Node server; `mlx_whisper` and `ffmpeg` must be on your `PATH` for the v0.2 media path.

## Optional GPT-5.6 mode

Keep API credentials on the server. Never place a key in `public/`, source code, screenshots, or commits.

```bash
export OPENAI_API_KEY="your-key"
export OPENAI_MODEL="gpt-5.6-terra"
npm start
```

When no key is configured, the app remains fully usable in local demo mode. Both the paste path (`/api/analyze`) and the media path (`/api/analyze-transcript`) honour this flag.

## v0.2 environment knobs

| Variable | Purpose | Default |
|---|---|---|
| `STORYCUT_MAX_UPLOAD_BYTES` | Upper bound for `/api/upload` body | `524288000` (500 MB) |
| `STORYCUT_WHISPER_MODEL` | MLX Whisper repo id for `tools/transcribe.py` | `mlx-community/whisper-small-mlx` |
| `STORYCUT_WORK_DIR` | Where uploaded media + cached transcripts live | `<repo>/.work` |
| `STORYCUT_SKIP_TRANSCRIBE_TESTS=1` | Skip the E2E transcribe test (e.g. in CI without the model cached) | unset |
| `STORYCUT_CACHE_DIR` | Root for local thumbnails and playback proxies | `~/Library/Caches/StoryCut` |
| `STORYCUT_PROJECT_INDEX_DIR` | Persistent project-index directory | `~/Library/Caches/StoryCut/project-index` |
| `STORYCUT_MEDIA_CACHE_MAX_BYTES` | Playback-proxy cache ceiling | `21474836480` (20 GB) |
| `STORYCUT_CACHE_RESERVE_BYTES` | Free local space retained while building a proxy | `1073741824` (1 GB) |
| `STORYCUT_PROXY_MAX_EDGE` | Playback-proxy maximum edge | `1280` |
| `STORYCUT_PROXY_VIDEO_BITRATE` | Target proxy video bitrate in bit/s | `2000000` |
| `STORYCUT_PROXY_AUDIO_BITRATE` | Proxy AAC bitrate in bit/s | `128000` |

## Privacy and security

- Source media is uploaded only to `127.0.0.1`; the bytes never leave the machine.
- Playback proxies and first-frame images stay in the current user's local StoryCut cache; source media and confirmed project versions are never modified.
- Transcript text is processed in memory and is not written to disk.
- Review subtitle corrections are written only to a project-local sidecar file; the source SRT/ASS is never overwritten.
- Recent project paths and pending notes stay in this browser's local cache and are never uploaded; clearing site data also clears this cache.
- The API key is read only from the server environment and is never returned to the browser.
- Raw media, transcripts, secrets, environment files, and common key formats are git-ignored. The single committed audio fixture (`tests/fixtures/short.mp3`) is whitelisted in `.gitignore` and `scripts/privacy-check.mjs`; adding a new fixture requires a security review per `HANDOFF.md`.
- Requests are limited to 200 KB (analyzer) and 500 MB (upload) by default.
- The server binds to `127.0.0.1` by default and sends restrictive browser security headers.
- Run `npm run privacy-check` before any public commit or submission.

See [SECURITY.md](SECURITY.md) for the disclosure policy and safe demo guidance.

## Test

```bash
npm test              # v0.1 analyzer tests + v0.2 adapter tests + v0.2 CLI E2E
npm run privacy-check # must be green before every public commit
```

`npm test` runs the analyzer, transcript adapter, local project workspace, review markers, version-safe subtitle corrections, conversational edit operations, local preview fallback, draft EDL persistence, and CLI integration tests. The CLI integration test is gated on `mlx_whisper` being importable; set `STORYCUT_SKIP_TRANSCRIBE_TESTS=1` to skip it.

## Architecture

```text
Browser review UI
       │
       ├── Paste path: /api/analyze            (v0.1, deterministic local)
       │                                       └── Optional GPT-5.6 via Responses API
       │
       └── Media path: /api/upload → /api/transcribe → /api/analyze-transcript (v0.2)
                              │                       │
                              ▼                       └── Same v0.1 decision engine
                          MLX Whisper                  (via src/adapter.mjs)
                          (tools/transcribe.py)
                                 │
                          Word-level timestamps
                                 │
                          Same {KEEP, CUT, MOVE, B-ROLL} proposals
                                 │
                          Human accept / reject
                                 │
                          Timeline JSON export
```

The optional AI path uses Structured Outputs so editorial decisions conform to a fixed schema. GPT-5.6 is used for editorial reasoning; deterministic code handles validation, alignment, review state, edit-operation parsing, local preview generation, and export.
